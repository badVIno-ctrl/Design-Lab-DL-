# Explainer — курсор для слабых ПК, идентичный курсор в iframe и фикс «недавнего сайта»

Разбор изменений из [PR #25](https://github.com/bboykorg/design-lab/pull/25). Четыре правки:

1. Кольцо-курсор не лагает на слабых ноутбуках (но анимация та же).
2. В превью-iframe рисуется **идентичный** курсор, и его больше **нет на телефонах**.
3. При простом входе больше не создаётся пустой «недавний сайт».
4. Сгенерированные ИИ блоки можно **перетаскивать** в Design-режиме, как в конструкторе.

---

## Background

design-lab — это ИИ-конструктор сайтов: один огромный `frontend/index.html` (~700 КБ)
и десятки маленьких патч-файлов (`*.js` / `*.css`), которые бэкенд на FastAPI подклеивает
в конец страницы. Порядок подклейки задан кортежем `_PATCH_SCRIPTS` в `backend/main.py`,
а `_build_index()` вставляет `<script src=…>` перед `</body>`.

> ⚠️ **Тонкость сборки.** `_build_index()` подключает патч, только если имени файла
> **ещё нет** в `index.html` (`for name in _PATCH_SCRIPTS if name not in raw`). Значит,
> буквально написать имя файла патча в комментарии внутри `index.html` — значит случайно
> **отключить** этот патч. На этом легко подорваться (я и подорвался — см. Verification).

Курсор устроен так. В `index.html` есть три элемента — `#cursorDot` (точка),
`#cursorRing` (кольцо), `#cursorGlow` (мягкое свечение) — и инлайновый IIFE, который
двигает их за мышью. Кольцо и свечение движутся не мгновенно, а «догоняют» курсор через
линейную интерполяцию (lerp) в цикле `requestAnimationFrame`. Отдельный патч
`iframe-cursor-bridge.js` рисует курсор **внутри** превью-iframe (`#pvFrame`), потому что
события мыши над iframe в родительский документ не попадают.

Основной курсор страницы уже корректно скрыт на телефонах: `dl-design-system.css`
(`html.dl-phone #cursorRing…{display:none}`) и `dl-mobile.js` (удаляет узлы). Класс
`dl-phone` ставит ранний скрипт в `<head>` при ширине ≤ 760px.

Список «Недавние сайты» — чисто клиентский `localStorage` (`dl_projects_v1`), который
наполняет `saveProject()`. Автосейв дёргается хуком поверх `renderHtml` и таймером
`scheduleAutosave()`.

## Intuition

**Курсор.** Старый цикл выглядел так: `requestAnimationFrame(loop)` крутился **вечно**,
даже когда мышь стоит и кольцу некуда двигаться — постоянная работа GPU/CPU впустую. Плюс
на каждое движение мыши создавался DOM-узел «следа», а таймер `setInterval(700ms)`
пробрасывал **синтетические `mousemove`** из iframe обратно в родителя, из-за чего на
каждое движение над превью заново считались параллакс, наклон карточек и след.
Представьте, что вы ведёте мышь над превью в конструкторе: вместо одной перерисовки
курсора страница делала десятки тяжёлых пересчётов в секунду. Это и есть «лаги на слабом
ноутбуке».

Идея фикса: кольцо всё так же плавно догоняет курсор, но цикл `rAF` **сам себя гасит**,
когда догнал (разница координат ≈ 0), и просыпается на следующем `mousemove`.
Синтетические `mousemove` вообще убираем — курсор в iframe рисует свой лёгкий слой. На
слабых устройствах отключаем только косметику (свечение, след, ripple), оставляя сам
кругляшок.

**Телефоны.** У основного курсора страницы гейт `(hover:hover) and (pointer:fine)` был,
а у `iframe-cursor-bridge.js` — нет. На телефоне палец рождает `pointermove`, кольцо в
iframe «зажигалось». Достаточно поставить тот же гейт.

**«Недавний сайт».** `openScratch()` кладёт в холст стартовую заглушку `starterHtml()`
(«Чистый холст») и рендерит её. Хук автосейва видел непустой `current.html` и заводил
карточку. А так как адрес `#editor/new` сохраняется, при каждой перезагрузке пустой холст
открывался заново и плодил ещё один «новый сайт». Решение: считать стартовую заглушку
«не проектом» и не сохранять её.

## Code

**1. `index.html` — idle-stop цикла и облегчение на слабых устройствах.**

```js
var reduce=matchMedia('(prefers-reduced-motion:reduce)').matches;
var LOW=reduce||(navigator.hardwareConcurrency||8)<=4||(navigator.deviceMemory||8)<=4;
if(LOW&&glow&&glow.parentNode){glow.parentNode.removeChild(glow);glow=null;}
var MAXTRAILS=LOW?0:10;
function tick(){
  raf=0;
  rx+=(mx-rx)*.18;ry+=(my-ry)*.18;ring.style.transform='translate('+rx+'px,'+ry+'px)';
  var far=(mx-rx)*(mx-rx)+(my-ry)*(my-ry);
  if(glow){gx+=(mx-gx)*.09;gy+=(my-gy)*.09;glow.style.transform='translate('+gx+'px,'+gy+'px)';var fg=(mx-gx)*(mx-gx)+(my-gy)*(my-gy);if(fg>far)far=fg;}
  if(far>0.05)raf=requestAnimationFrame(tick);   // догнал — цикл гаснет
}
function kick(){if(!raf)raf=requestAnimationFrame(tick);}  // просыпаемся на mousemove
```

Там же **удалён** старый `bridgeFrame()` + `setInterval(…,700)`, который слал
синтетические `mousemove` из iframe в родителя. Именно он грузил конструктор.

**2. `iframe-cursor-bridge.js` — идентичный вид, гейт по устройству, прятать родительский курсор.**

```js
// на телефонах/планшетах курсора нет вовсе
if(!window.matchMedia||!matchMedia('(hover:hover) and (pointer:fine)').matches) return;
// стили 1-в-1 как #cursorRing/#cursorDot: 36px кольцо, 9px точка, те же цвета/тени
// точка мгновенно, кольцо lerp'ом с тем же .18 и idle-stop
function move(e){ x=e.clientX; y=e.clientY; parentCursorOpacity('0'); if(!raf) raf=win.requestAnimationFrame(frameFn); }
```

Пока указатель над кадром, `parentCursorOpacity('0')` прячет `#cursorDot/#cursorRing/#cursorGlow`
родителя, чтобы фиксированное кольцо не застыло у края iframe и не двоилось; на
`pointerleave` — возвращаем.

**3. `index.html` — не сохранять пустой холст.**

```js
function dlIsBlankCanvas(h){
  if(!h)return true;
  if(typeof starterHtml==='function'&&h===starterHtml())return true;
  return h.indexOf('Чистый холст')>=0;
}
function saveProject(manual){
  if(!current||!current.html){/* нечего сохранять */return;}
  if(dlIsBlankCanvas(current.html)){/* пустой стартер — не проект */return;}
  /* … */
}
```

Плюс в хуке `renderHtml` автосейв планируется только для непустого холста. Гард стоит в
`saveProject` — это единая точка для всех путей автосейва (таймер, design-режим, правка
текста), поэтому пустой холст не запишется ниоткуда.

**4. `design-move-free.js` — перетаскивание сгенерированных блоков в Design-режиме.**

В основном редакторе ИИ пишет готовый HTML в превью; там можно было править текст и тянуть
размер, но не двигать блоки. Новый патч добавляет именно перемещение: у наведённого блока
в углу появляется круглая ручка, за неё блок перетаскивается. Сдвиг — через
`transform: translate(...)`, ровно как «свободный сдвиг» узлов в SF-конструкторе
(`shiftX/shiftY`): поток документа не ломается, соседи не прыгают.

```js
function setTranslate(el, x, y) {
  var rest = (el.style.transform || '').replace(/translate\([^)]*\)/, '').trim();
  el.style.transform = ('translate(' + Math.round(x) + 'px,' + Math.round(y) + 'px) ' + rest).trim();
}
// тащим только за ручку → клик по тексту и contenteditable не ломаются
handle.addEventListener('mousedown', function (e) {
  if (!inDesign() || !cur) return;
  e.preventDefault(); e.stopPropagation();
  drag = { el: cur, sx: e.clientX, sy: e.clientY, /* … */ };
}, true);
```

Аккуратность: патч работает только когда `boardMode === 'design'`; ручку и её стиль
временно снимаем перед сериализацией, чтобы они не попали в сохраняемый HTML; сдвиг сразу
уходит в `current.html`, в код и в автосейв. Патч зарегистрирован в `_PATCH_SCRIPTS`
(`backend/main.py`) сразу после `design-resize-free.js`.

> 🧩 **Почему ручка, а не «схватить сам блок».** В Design-режиме весь документ
> `designMode='on'` (contenteditable). Если начинать перетаскивание по обычному
> `mousedown` на элементе, это конфликтует с установкой каретки и выделением текста.
> Отдельная ручка не трогает текстовые клики — правка текста и растягивание работают
> ровно как раньше.

## Verification

- **Автоматически:** `node --check` по всем 23 инлайновым `<script>` в `index.html` и по
  `iframe-cursor-bridge.js` / `design-move-free.js` — без ошибок. Бэкенд-скрипты
  `test_backend.py`, `test_auth.py`, `test_stream.py` — зелёные. Предвыходные фейлы в
  `test_security.py`/`test_skill_packs.py` уже были на `main` и не связаны с этой правкой
  (менялся только фронтенд + регистрация патча). Проверено, что `_build_index()`
  подключает новый `design-move-free.js`.
- Отдельно проверил, что `_build_index()` по-прежнему подключает **все** патчи. Сначала я
  случайно написал имя `iframe-cursor-bridge.js` в комментарии внутри `index.html`, и
  self-guard по имени файла **выкинул** патч из сборки. Комментарий переписал — патч снова
  подключается.

**Ручная QA** (нужен запуск `uvicorn backend.main:app`):

1. Десктоп: поводить мышью — кольцо/точка/след как раньше; в простое (мышь стоит) в
   DevTools → Performance нет постоянных кадров rAF.
2. Конструктор: водить мышью над превью — плавно, без рывков; курсор в поле iframe
   выглядит так же, как на странице.
3. Телефон (или DevTools device toolbar) — кругляшка нет ни на странице, ни в превью.
4. Открыть с адресом `#editor/new`, перезагрузить пару раз — новые пустые карточки в
   «Недавних сайтах» не появляются; после реальной генерации сайт сохраняется как обычно.
5. Сгенерировать сайт, включить режим **Design**, навести на блок — в углу появляется
   круглая ручка; потащить за неё — блок двигается, при отпускании сдвиг попадает в код и
   автосейв. Клик по тексту (каретка) и растягивание при этом работают как прежде.

## Alternatives

| Подход к курсору над iframe | Плюсы | Минусы |
| --- | --- | --- |
| **Убрать синтетические mousemove, рисовать курсор внутри iframe (выбрано)** | Снимает главный источник лагов; один лёгкий слой; совпадает с просьбой «идентичный курсор в поле iframe» | На редких сайтах со своим кастомным курсором теоретически возможно задвоение |
| Оставить проброс, но троттлить его | Родительское кольцо «само» ездит над iframe без второго слоя | Всё равно будит параллакс/наклон/след родителя; край iframe даёт рывки; не решает «курсор именно внутри поля» |

| Подход к простою курсора | Плюсы | Минусы |
| --- | --- | --- |
| **Idle-stop rAF (выбрано)** | Ноль работы в простое, анимация та же при движении; минимальная правка | Нужно не забыть `kick()` во всех точках пробуждения (mousemove, mouseenter) |
| Просто понизить FPS / убрать эффекты у всех | Ещё проще | Ломает просьбу «чтобы все анимации работали также» на нормальных ПК |

## Quiz

<details>
<summary>1. Почему старый курсор грузил именно конструктор (превью-iframe)?</summary>

- А. Кольцо было слишком большим.
- **Б. `setInterval` слал синтетические `mousemove` из iframe в родителя, заново считая параллакс/наклон/след. ✔**
- В. iframe перерисовывался целиком.

Верно Б: проброс событий будил все тяжёлые обработчики родителя на каждое движение над
превью. А — вид не влияет на CPU; В — перерисовок iframe тут не было.
</details>

<details>
<summary>2. Что делает idle-stop с циклом requestAnimationFrame?</summary>

- А. Ограничивает FPS до 30.
- **Б. Останавливает цикл, когда кольцо догнало курсор, и будит его на mousemove. ✔**
- В. Полностью выключает анимацию кольца.

Верно Б. А — частоту не трогаем; В — анимация остаётся, просто не крутится вхолостую.
</details>

<details>
<summary>3. Почему кругляшок появлялся на телефонах?</summary>

- **А. `iframe-cursor-bridge.js` не имел гейта `(hover:hover) and (pointer:fine)`, а касание рождает `pointermove`. ✔**
- Б. CSS основного курсора не был скрыт на `dl-phone`.
- В. Телефон эмулирует мышь.

Верно А. Основной курсор как раз корректно скрыт на `dl-phone` (`dl-design-system.css` +
`dl-mobile.js`) — проблема была только в патче iframe.
</details>

<details>
<summary>4. Почему при простом входе плодился «новый сайт»?</summary>

- А. Сервер создавал проект на каждый GET.
- **Б. `openScratch()` рендерил `starterHtml()`, автосейв сохранял его, а хэш `#editor/new` при перезагрузке повторял это. ✔**
- В. `session-restore.js` восстанавливал удалённые проекты.

Верно Б. Список «Недавние» — клиентский `localStorage`, наполняемый `saveProject()`;
пустой стартер туда попадать не должен.
</details>

<details>
<summary>5. Почему нельзя писать имя патч-файла в комментарии внутри index.html?</summary>

- А. Ломается подсветка синтаксиса.
- **Б. `_build_index()` пропускает патч, если его имя уже встречается в `index.html` (`name not in raw`). ✔**
- В. Увеличивается размер файла.

Верно Б: self-guard решает, что патч уже подключён, и не вставляет `<script>` — патч тихо
пропадает.
</details>
