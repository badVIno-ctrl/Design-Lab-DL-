# Дизайн-паки

Каждый файл в `packs/` — один свод правил, который дописывается в системный
промпт модели. Отбор паков зависит от модели: см. `../DESIGN-SKILLS.md`.

## Формат

```
---
id: layout-craft          # совпадает с именем файла
title: Композиция и сетка # заголовок в промпте
priority: 25              # порядок; < 20 = обязательный минимум для всех
tiers: small, mid, large, frontier   # каким классам моделей давать «по весу»
                                     # none — только по теме запроса
modes: any                # any | scratch | edit
intent: сетка, layout, grid, отступ  # слова в запросе, поднимающие пак
needs: vision             # требование к модели: vision | reasoning
sources: kто автор идей   # обязательно, см. SOURCES.md
---
Тело пака: императивные правила, по одному на строку.
```

## Правила написания пака

- **Императив, не проза.** «Радиус вложенного = внешний минус отступ», а не
  «важно помнить, что радиусы вложенных элементов влияют на восприятие».
- **Числа вместо прилагательных.** `scale(0.96)`, `line-height 1.5–1.7`,
  `96–128px между секциями`. Модель не умеет исполнить «щедрые отступы».
- **1–2.5 тыс. символов.** Пак крупнее 2.5 тыс. не влезет в бюджет средних
  моделей и будет молча отброшен — проверьте `tools/build_skill_packs.py`.
- **Ни одной ссылки на другой файл.** Модель не может ничего открыть.
- **Приоритет уникален.** На этом держится порядок в промпте; тест проверяет.
- **`sources` обязателен.** Тест падает, если поле пустое.

## Проверка после правки

```bash
python3 tools/build_skill_packs.py        # пересобрать frontend/dl-skill-packs.json
python3 backend/test_skill_packs.py       # 39 проверок отбора и бюджетов
python3 backend/test_skill_packs.py --dump > /tmp/expected.json
node tools/test_skill_packs_parity.js /tmp/expected.json   # сверка с браузером
```

Забыть пересборку легко, и тогда сервер и браузер начнут давать модели разные
правила. Сверка `test_skill_packs_parity.js` существует именно для этого.
